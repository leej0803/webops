Monthly workflow

Incentives
Process

Four-step workflow for monthly offer removal, copy deck review, deployment, and post-launch change management.

01

End of month

Offer Removal

Desktop & Mobile — VLP, Why, Core Offers, HP Banner, Local Offers

▾
IWA DP
Submits JIRA tickets internally and to HAEA JIRA.
HAEA
Responsible for the following pages (as of July 1, 2017):
  • Ioniq VLP — Mobile
  • Ioniq Why — Desktop & Mobile
  • Sonata Plug-in — Desktop & Mobile
  • Elantra VLP — Desktop
  • Elantra Enhanced Why — Desktop & Mobile
  • HP Banners — Desktop
  • Core Offers page
  • Local Offers Image (if needed) — Desktop & Mobile
Timing
Two days prior to the last day of the offer cycle.
IWA
Updates and deploys all pages to QAWeb / SWeb with generic offers.
QA
Signs off on all environments — QAWeb, SWeb, and Production.
IWA WebOps
Submits HAEA file list JIRA ticket for deployment.
IWA BM
Notifies HMA that removal is complete.
Offers removed on production
02

Offers announced

Copy Deck Preparation

New offer copy deck review and distribution

▾
HMA Incentives
Offers are announced.
HMA Marketing
Works with the sales team to select featured offers and updates the previous month's copy deck.
HMA Marketing
Sends copy deck with tracked changes, proper disclaimers, and the integrated offer grid.
IWA no longer QAs the deck to expedite timing. What HMA sends is assumed final.
AM
Shares copy deck with CRM, In Market, and Digital Production.
03

Deployment

Updates & Deployment

Desktop, Mobile, and Footers

▾
DP
Connects with studio to cut necessary assets for HP Banner and Core Offers page.
IWA DP
Creates HAEA and IWA JIRA tickets. Ensures all necessary assets are attached with the deck.
HAEA
Responsible for the following pages (as of July 1, 2017):
  • Ioniq VLP — Mobile
  • Ioniq Why — Desktop & Mobile
  • Sonata Plug-in — Desktop & Mobile
  • Elantra VLP — Desktop
  • Elantra Enhanced Why — Desktop & Mobile
  • HP Banners — Desktop
  • Core Offers page
  • Local Offers Image (if needed) — Desktop & Mobile
IWA / HAEA
Updates and deploys all pages to QAWeb, SWeb, and SMobile.
IWA QA
Signs off on all environments for templated pages.
HAEA QA
Signs off on all environments for non-templated pages. IWA confirms updates are correct across all environments.
IWA BM
Submits staging links to HMA Marketing for approval.
Offer alterations may require repeating steps 2 and 3, which may delay the push to production.
IWA WebOps
Submits HAEA file list JIRA ticket for deployment.
HAEA
Approves file list. IWA WebOps deploys and verifies on Production — desktop and mobile.
Production complete
04

Post-launch

Running Changes

Desktop & Mobile post-launch change management

▾
HMA — Major
Major post-launch changes requiring immediate action will affect timing on everything else in the IWA WebOps / HAEA queue.
HMA — Minor
Minor post-launch changes are added to the IWA WebOps / HAEA queue for normal processing.
Production complete

G.COM INCENTIVES PROCESS

Step 1: End of Month - Offer Removal

Offer Removal for Campaign Pages (Desktop / Mobile)

  • - IWA JIRA: Automated JIRA issue generated
  • - IWA WebOps: Confirms with BM and proceeds with removal of offers
    • Authoring removal on prod author (environment)
    • Author starts workflow
    • QA recieves notification on JIRA
    • QA performs testing on prod author
    • QA completes workflow on production
    • Post QA on production verifies and closes JIRA issue
  • - IWA BM: Notifies GMA offers are removed
    • Offers Removed On Production

Step 2: New Offer Copy Deck Preparation

OFFERS ANNOUNCED

  • - HMA Incentives: Offers are announced updates made with HAEA on promotions page
  • - HMA Marketing: Notifies IWA BM
  • - IWA BM: Creates offers deck copying updates from promotions page shares with IWA DP
  • - IWA DP: QA's deck for discrepancies and routes to proofing
    • If discrepencies are found, IWA BM: sends created deck back to GMA for confirmation (this may delay process)
  • - IWA DP: Creates JIRA issue providing copy decks / assets assigning to IWA WebOps

Step 3: New Offer Updates and Deployments

New Offer Updates and Deployments (Desktop / Mobile)

  • - IWA WebOps: Proceeds with Offer updates
    • Authoring update on prod author (environment)
    • Author starts workflow
    • QA recieves notification on JIRA
    • QA performs testing on prod author
    • QA completes workflow on production
    • Post QA on production verifies and closes JIRA issue
  • - IWA BM: Notifies GMA offers are live on production
    Production Complete

Step 4: Running Changes - Desktop/Mobile

RUNNING CHANGES

  • - Major post launch changes identified by GMA that need to be immediately addressed will affect timing on everything else in IWA WebOps / HAEA queue.
  • - Minor post launch changes identified by GMA will be added to IWA WebOps / HAEA queue.

Production Complete

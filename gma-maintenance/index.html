G.COM MAINTENANCE PROCESS

Project Information

REQUEST

  • GMA: Podio Request due from client
  • BM: After confirming details, send details to production for assignment
  • DP: Review maintenance request
    • If everything looks good, proceed with update
    • If any questions, push back to get further clarification

DESIGN/COLLECT

  • DP: Gather necessary assets/documentation for WebOps
  • DP: Create JIRA ticket
    • For maintenance that touches multiple pages, create an epic with stories
    • Ensure proper BM and DP resources are attached to the ticket
    • Ensure proper production dates are noted in the ticket
    • If the update needs to push out with an existing request, link the tickets
  • DP: Assign ticket to WebOps

Authoring & QA

DEVELOP/AEM

  • WebOps: Review the ticket and work with DP to address questions or concerns
    • Are staging/prod dates feasible?
    • Any missing assets/documentation necessary for request?
    • Are there any conflicting updates?
    • Enter necessary content for update

TEST/DEPLOY

  • WebOps: Authors updates on prod author and starts workflow
    • QA recieves notification via JIRA and performs testing on prod author
    • QA completes workflow and verifies on production
    • QA closes JIRA issue
  • BM: Notifies GMA update is complete

Production Complete
